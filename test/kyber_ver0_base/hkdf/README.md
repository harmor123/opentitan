# 测试说明

## 一.hkdf

#### 1.python验证

`HKDF-exp.py`

#### 2. API 接口规范
##### 2.1 函数调用
```assembly
jal x1, hkdf
```
##### 2.2 输入参数 (调用前需设置)
| 寄存器                                                       | 描述                               | 约束                                               |
| :----------------------------------------------------------- | :--------------------------------- | :------------------------------------------------- |
| `x10`                                                        | 指向 Salt (盐值) 数据的指针        | 无需 32 字节对齐。若 `x11`=0，此指针可指向任意地址 |
| `x11`                                                        | Salt 的长度 (字节数)               | `>= 0`。若为 0，内部自动替换为 32 字节全零串       |
| `x12`                                                        | 指向 IKM (输入密钥材料) 的指针     | 无需 32 字节对齐                                   |
| `x13`                                                        | IKM 的长度 (字节数)                | `> 0`                                              |
| `x14`                                                        | 指向 Info (上下文信息) 的指针      | 无需 32 字节对齐。若 `x15`=0，此指针可指向任意地址 |
| `x15`                                                        | Info 的长度 (字节数)               | `>= 0`                                             |
| `x16`                                                        | 期望输出的总长度 L (字节数)        | `> 0`，最大 `255 * 32 = 8160`                      |
| `x17`                                                        | 指向输出 OKM (输出密钥材料) 的指针 | 建议至少 4 字节对齐，需保证至少有 L 字节的有效空间 |
| 注：函数内部会调用 Extract 和 Expand，最大栈深约消耗 128 字节（含内层 64 字节），调用者需保证栈指针 `sp` 正常且不与内部缓冲区冲突。 |                                    |                                                    |
##### 2.3 输出结果
函数执行完毕后，长度为 `L` 字节的派生密钥将被写入 `x17` 指向的内存中。中间态 PRK 由模块内部私有空间自动管理，调用者无感。
##### 2.4 内部依赖函数
`hkdf` 为总控包装函数，内部会依次调用以下私有及外部函数（需由链接脚本提供）：
1. `_hkdf_extract_internal(x10=salt, x11=salt_len, x12=ikm, x13=ikm_len, x14=_int_prk_buf)`
2. `_hkdf_expand_internal(x10=prk, x11=32, x12=info, x13=L, x14=okm, x15=info_len)`
3. `hmac(x10=key, x11=key_len, x12=msg, x13=msg_len, x14=out)` （依次调用 `sha3_init`, `sha3_update`, `sha3_final`）
---
#### 3. 大小端序 说明
本架构为严格的小端序。这在编写测试数据时极其容易出错，必须遵循以下规则：
##### 3.1 字符串/字节数组的内存排布
假设你要输入 Info = `"f0f1f2f3f4f5f6f7f8f9"`（对应十六进制 `f0 f1 f2 f3 f4 f5 f6 f7 f8 f9`，共 10 字节）：
* **低地址放低字节**。
* 在汇编中使用 `.word` 倒序拼接，且如果长度不是 4 的倍数，最后一个 `.word` 的高位需补 `0x00`（内部移位掩码逻辑会自动剔除无效位，**绝不会多算字节**）：
```assembly
.balign 4
my_info:
    .word 0xf3f2f1f0    /* 对应 f0 f1 f2 f3 */
    .word 0xf7f6f5f4    /* 对应 f4 f5 f6 f7 */
    .word 0x00000000    
    /* 修正：应该是 .word 0x00f9f8f7 不对，应该是把 f8 f9 放低位，高位补 00 */
    /* 正确写法：*/
    .word 0x00f9f8f8    /* 错误示例，下面有正确示例 */
```
**正确写法**：
```assembly
.balign 4
my_info:
    .word 0xf3f2f1f0    /* f0 f1 f2 f3 */
    .word 0xf7f6f5f4    /* f4 f5 f6 f7 */
    .word 0x0000f9f8    /* f8 f9 00 00 (高位自动被截断) */
```
##### 3.2 哈希输出结果的比对
假设通过 Python 算出的 OKM 理论值（大端人类可读格式）前 4 字节为：`9134fd8e`
在 DMEM 内存（小端序）中，它的实际存储形态将是倒序的：
```assembly
    .word 0x8efd3491    /* 对应 91 34 fd 8e 倒序 */
```

#### 4. 测试代码内存布局说明
在 `.data` 段中，必须严格按照以下结构和大小端对齐分配变量。**特别注意 `hkdf_` 前缀的专属缓冲区，绝对不可改名！**
```assembly
.data
/* 1. 栈空间：必须 32 字节对齐 */
.balign 32
stack:
  .zero 1024
stack_end:
/* 2. SHA3 上下文：存放内部状态 */
.balign 32
context:
  .zero 212
/* 3. Keccak 轮常数：由于 bn.lid 指令按 32 字节步长读取，必须强行 .balign 32 */
.balign 32
rc:
.balign 32
  .dword 0x0000000000000001
.balign 32
  .dword 0x0000000000008082
  /* ... 共 24 个轮常数 ... */
/* 4. HMAC 辅助缓冲区 */
.balign 32
inner_hash:
  .zero 32
.balign 32
key_buf:
  .zero 200    /* 预留 200 字节防止 BN 指令越界读脏数据 */
.balign 32
ipad:
  .zero 200
.balign 32
opad:
  .zero 200
/* ==========================================
 * 5. HKDF 专属隔离区 (极其关键！不可改名！)
 * ========================================== */
/* HKDF-Expand 消息拼接区：T_prev + info + counter */
.balign 32
.globl hkdf_msg_buf    /* 绝对不能叫 msg_buf！防止被 sha3 内部覆盖 */
hkdf_msg_buf:
  .zero 320            /* 预留足够大空间 */
/* HKDF-Expand 循环状态安全屋 */
.balign 32
.globl hkdf_ctx        /* sha3 绝对不会碰这个区域 */
hkdf_ctx:
  .zero 64
/* 单次 HMAC 结果暂存区 */
.balign 32
.globl t_buf
t_buf:
  .zero 32
/* 注：_int_prk_buf 和 _int_default_salt 已封装在 hkdf.s 内部，测试文件无需声明！ */
```

#### 5. 如何修改测试用例
##### 场景 A：测试空 Salt (默认全零盐值)
按照 RFC 5869，如果 `salt_len = 0`，函数会自动使用 32 字节的 `0x00`。
在 `main` 中修改：
```assembly
  la      x10, test_ikm      /* 随便复用个有效地址即可，因为不会被读 */
  li      x11, 0             /* 核心：salt_len = 0 */
  la      x12, test_ikm      /* ikm_ptr */
  li      x13, 22            /* ikm_len */
  /* ... info 和 L 正常传入 ... */
```
##### 场景 B：测试空 Info (`info = b""`)
在 `main` 中修改：
```assembly
  /* ... salt 和 ikm 正常传入 ... */
  la      x14, test_ikm      /* 随便复用个有效地址 */
  li      x15, 0             /* 核心：info_len = 0 */
  li      x16, 64            /* L */
  la      x17, final_okm
```
##### 场景 C：测试长字符串 Info (如 "Hybrid key exchange"，20 字节)
假设要输入 Info = `"Hybrid key exchange"` (对应 ASCII：`48 79 62 72 69 64 20 6b 65 79 20 65 78 63 68 61 6e 67 65`)：
在 `.data` 中按小端序拼接（每 4 字节倒序，最后不足 4 字节高位补 0）：
```assembly
.balign 4
test_info:
    .word 0x6b207962    /* "by k" 倒序 -> 62 79 62 20 6b */
    .word 0x20646948    /* "Hid " 倒序 -> 48 69 64 20 */
    .word 0x79616863    /* "chay" 倒序 -> 63 68 61 79 */
    .word 0x63617078    /* "xpac" 倒序 -> 78 70 61 63 */
    .word 0x00656e67    /* "gne" + 0x00 -> 67 6e 65 00 */
```
对应 `main` 中：
```assembly
  la      x14, test_info
  li      x15, 20            /* 必须精确设为 20，内部会自动把最后一个 0x00 剔除 */
```

## 三.hkdf_expand

#### 2. API接口规范
##### 2.1 函数调用
```assembly
jal x1, hkdf_expand
```
##### 2.2 输入参数 (调用前需设置)
| 寄存器 | 描述                          | 约束                                      |
| :----- | :---------------------------- | :---------------------------------------- |
| `x10`  | 指向 PRK (伪随机密钥) 的指针  | **必须恰好为 32 字节** (SHA3-256输出长度) |
| `x11`  | 指向 Info (上下文信息) 的指针 | 无需 32 字节对齐，可为 `b''` (空)         |
| `x12`  | Info 的长度 (字节数)          | `>= 0`，最大 255                          |
| `x13`  | 期望输出的总长度 L (字节数)   | `> 0`，最大 `255 * 32 = 8160`             |
| `x14`  | 指向输出 OKM 的指针           | 建议至少 4 字节对齐，空间 >= L            |
##### 2.3 输出结果
* 函数执行完毕后，长度为 `L` 字节的派生密钥将被写入 `x14` 指向的内存中。
---
#### 3. 大小端序 说明
**本架构为严格的小端序。** 这在填充 `info` 数据时极易出错：
##### 3.1 Info 字符串的内存排布
假设要传入 Info = `"f0 f1 f2"`（3字节）：
* **低地址放低字节**。
* 在汇编中使用 `.word` 倒序拼接，且高位补 `0x00`：
```assembly
.balign 4
my_info:
    .word 0x00f2f1f0    /* 对应 0xf0, 0xf1, 0xf2, 0x00(无效位) */
```
* 此时 `x12` 必须设为 `3`，汇编内的尾部掩码逻辑会自动把最后一个 `0x00` 剔除，**绝不会多算一个字节**。
##### 3.2 最终输出 OKM 的比对
输出结果在 DMEM 中是以小端序按字存储的。如果你的 Python 脚本输出了大端的 OKM：
`039e7b28e10a2d20...`
在内存/二进制文件中的实际排列（以 4 字节为单位倒序）：
```assembly
/* 对应前4字节 03 9e 7b 28 的实际存储 */
    .word 0x287b9e03
/* 对应接下来 4字节 e1 0a 2d 20 的实际存储 */
    .word 0x202d0ae1
```
#### 4. 测试代码内存布局说明
由于防冲突机制，HKDF 测试代码对 `.data` 段的命名和空间要求极其严格：
```assembly
.data
/* 1. 栈空间 */
.balign 32
stack:
  .zero 1024
/* 2. SHA3 内部依赖 (必须存在且命名不可改) */
.balign 32
context:     .zero 212
rc:          ... (24个轮常数，需 .balign 32 填充)
inner_hash:  .zero 32
key_buf:     .zero 200
ipad:        .zero 200
opad:        .zero 200
/* ==========================================
 * 3. HKDF 专属隔离区 (极其关键！)
 * ========================================== */
/* 消息拼接区：T_prev(32) + info(最大255) + counter(1) = 288 */
.balign 32
.globl hkdf_msg_buf    /* 绝对不能叫 msg_buf！ */
hkdf_msg_buf:
  .zero 320            /* 预留大一点，防止 BN 指令越界读脏数据 */
/* 状态安全屋：存放 N, i, offset 等 */
.balign 32
.globl hkdf_ctx
hkdf_ctx:
  .zero 64             /* sha3 绝对不会碰这个区域 */
/* 单次 HMAC 结果暂存 */
.balign 32
.globl t_buf
t_buf:
  .zero 32
```

#### 5. 如何修改测试用例
##### 场景 A：测试空 Info (`info = b""`)
如果你的协议不需要上下文（如之前提到的混合密钥例子中 `info=b""`）：
1. 随便指向一个地址（因为长度为 0 不会发生实际读取）：
   ```assembly
   la      x11, hkdf_ctx     /* 随便复用个地址即可 */
   li      x12, 0            /* 核心：info_len = 0 */
   ```
2. 此时第一轮的 `msg` 实际上只有 1 个字节 `0x01`，第二轮有 33 个字节（`T(1)` + `0x02`）。
##### 场景 B：测试只输出 32 字节 (`L = 32`)
1. 修改 `x13`：
   ```assembly
   li      x13, 32
   ```
2. 内部只会执行 1 次循环（`N=1`），不会发生 `T_prev` 的拷贝，逻辑走最简路径。
##### 场景 C：测试长 Info (如 20 字节字符串)
假设 Info = `"Hybrid key exchange"` (20 字节)：
```assembly
.balign 4
my_info:
    .word 0x6b207962    /* "by k" 倒序 */
    .word 0x20646948    /* "Hid " 倒序 */
    .word 0x79616863    /* "chay" 倒序 */
    .word 0x63617078    /* "xpac" 倒序 */
    .word 0x00656e67    /* "gne\0" 倒序 */
/* 对应 main 中： */
/* la      x11, my_info */
/* li      x12, 20 */
```
*(注：20 字节不是 4 的整数倍，代码里的 `copy_info_tail` 会自动用 `andi` 掩掉最后一个字的最高字节 `0x00`，精准传入 20 字节，无需手动垫位！)*
